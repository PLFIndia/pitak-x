## Understanding

Three presentation-only changes, no domain/schema/FFI impact:

1. **Availability tag colours, consistent with the web viewer.** The web
   site (`assets/publish/index.html:190-194`) uses green `#1b5e20` for
   *Available* and red `#b00020` for *Not available* (dark text `#7fdf95` /
   `#ff8a80`). In the app both tags use `secondaryContainer`:
   - `lib/features/network/presentation/widgets/published_item_badges.dart:52-60`
     (in-app viewer, `emphasised: true` for both states);
   - `lib/features/library/presentation/widgets/catalogue_item_row.dart:128-133`
     and `catalogue_item_grid_card.dart:114-119` (own library list, "Not
     available" pill).
   Decision: **consistent** — red for *Not available* everywhere, green for
   *Available* in the viewer (the library list never shows "Available").

2. **Borrowers vault.** Replace the `Icons.rule` app-bar action with an
   expandable "Lending rules" card at the top of the unlocked borrower list
   (mockup Option A: status pill in header, explicit Save inside). Drop the
   bell (`PendingPage`). Only **Lock** stays in the app bar.
   `vault_page.dart:38-63`.

3. **Borrowed Items.** Replace both the `Icons.message_outlined` app-bar
   action (→ `ReminderTemplatesPage`) and the existing dropdown
   `_TemplateSelector` (`borrowed_items_content.dart:124-189`) with one
   expandable "Reminder message" card (mockup Option B): template chips in
   the header (tap = select, saves immediately, plus a "+" chip to add),
   expanded body = the selected template's three bodies (overdue / upcoming
   / no due date — `ReminderTemplate` has three, not one) with Edit /
   Duplicate / Delete for custom templates and the storage note.

4. **Shelf location on the home catalogue cards (app only).** Show
   `CatalogueItem.location` (trimmed, non-empty) as a third text line under
   the author in `catalogue_item_row.dart` and `catalogue_item_grid_card.dart`:
   small shelf icon + bold text (`fontWeight: FontWeight.w600`), colour
   `onSurface` normally, the `AvailabilityColors.unavailableFg` red when
   `unavailable && !removed` (same predicate as the badge). Semantics label
   "Shelf location: <value>". Nothing changes on the publish side —
   `location` is already stripped from `books.json`.

## Privacy & threat notes

- No new data, storage, permissions or network. Template text is already
  device-local, unencrypted by design, and already shown on the manager
  page; showing the selected body on Borrowed Items changes *where* it
  renders, not its exposure. Vault-gated content stays behind
  `VaultUnlocked` exactly as today (the card lives inside
  `BorrowedItemsContent`, which is only built when unlocked).
- Lending rules are device-local preferences without borrower data
  (`lending_rules_page.dart:1`); moving the editor onto the vault page does
  not change that. It stays visible in locked/uninitialized states?
  **Decision point 2** below.

- Shelf location is private library-operations data; it already never
  leaves the device via publish (`catalogue_item.dart:199`). Showing it on
  the list is the same exposure as the detail page.

## Proposed approach

### 1. Availability colours
- Add `AvailabilityColors extends ThemeExtension` in `app_theme.dart`
  (Flutter's documented mechanism for app-specific semantic colours —
  `ThemeExtension` API docs; same pattern as Material's own
  `ColorScheme`), with `available{Bg,Fg}` and `unavailable{Bg,Fg}` for
  light and dark, mirroring the web hexes. Register on both `ThemeData`s.
- `published_item_badges.dart`: replace `bool emphasised` with
  `enum _BadgeTone { neutral, available, unavailable }`.
- `catalogue_item_row.dart` / `catalogue_item_grid_card.dart`: "Not
  available" pill reads `AvailabilityColors.unavailable*`.
- Tests: contrast test for the four pairs against `AppTheme` surfaces
  (`contrastRatio ≥ 4.5`); badge colour assertions in the two viewer page
  tests; regenerate 4 goldens.

### 2. Lending rules card + bell removal
- New `lib/features/vault/presentation/widgets/lending_rules_card.dart`:
  `ExpansionTile` inside a `Card` (Material's own expandable pattern;
  avoids a custom animation). Header: title, subtitle, status pill
  (`Off` / `Max N · Warn|Refuse`) read from `lendingRulesControllerProvider`.
  Body: the extracted `LendingRulesForm` (moved out of
  `lending_rules_page.dart` unchanged in behaviour).
- `vault_page.dart`: remove both actions; `_BorrowerList` becomes a
  `ListView` with the card first, then borrowers (so the card scrolls with
  the list and the FAB still works).
- Delete `pending_page.dart`, `lending_rules_page.dart` (if no other
  caller) and the now-dead `pendingSnapshotProvider` chain — only after
  confirming via `rg`.
- Tests: move `lending_rules_page_test.dart` assertions to the card;
  `vault_page_test.dart`: no rule/bell icons, card present when unlocked,
  save path works; a11y gate.

### 3. Reminder message chip card
- New `lib/features/vault/presentation/widgets/reminder_template_card.dart`:
  `Card` + `ExpansionTile`; header `title` = "Reminder message", header
  `subtitle` = `Wrap` of `ChoiceChip`s (one per `allTemplates`, selected =
  `selectedTemplateId`) + an "Add" `ActionChip`. Tap → `select(id)`;
  failure → SnackBar (same wording as today). Body: three labelled bodies
  of the selected template; `Edit` / `Duplicate` / `Delete` `TextButton`s
  for custom templates (reuse `ReminderTemplateEditorPage` and the
  existing delete confirmation); the storage note; unavailable-selection
  warning (current behaviour, `reminder_templates_page.dart:106-113`).
- `borrowed_items_content.dart`: replace `_TemplateSelector` with the card.
- `borrowed_items_page.dart`: remove the app-bar action.
- `ReminderTemplatesPage`: delete, **or** keep only as the error-recovery
  surface (decision point 3).
- Tests: port `reminder_templates_page_test.dart` cases (select, add,
  duplicate, delete, unavailable selection, reset) to the card; update
  `borrowed_items_page_test.dart` for the dropdown → chips change; a11y.

### 4. Shelf location line
- Both list widgets: `if (book.location?.trim().isNotEmpty ?? false)` →
  `Row(Icon(size 14), SizedBox(4), Expanded(Text(..., maxLines: 1,
  ellipsis)))` wrapped in `Semantics(label: 'Shelf location: …')` with
  `excludeSemantics` on the icon. Row uses `bodyMedium`, grid `bodySmall`.
- Colour: `unavailable && !book.removed ? availability.unavailableFg :
  scheme.onSurface`; weight w600.
- Tests: `catalogue_item_row_test` / grid-card test (find existing files):
  shown when set, hidden when null/blank, red when unavailable, onSurface
  otherwise; contrast via the a11y gate; the two library goldens pick it up
  (add a location to one fixture item).

## Review follow-up (2026-11-09)

Self-review of the implementation found one Major and several Minor issues;
the maintainer approved fixing all of them (goldens/CI stay last).

**Root cause of the Major:** both cards were bolted onto layouts that were
not designed to hold them. Borrowed Items stacked the template card in a
`Column` above an `Expanded` list, so only the *expanded body* was capped
(40 %) while the chip header (up to 21 chips: 20 custom + English) was
unbounded. A probe reproduced `RenderFlex` overflows: landscape 915×412
expanded with 2 templates; any orientation with 20. The vault page put the
lending-rules card at index 0 of a lazy `ListView.builder`, so scrolling far
away disposed it and lost unsaved edits.

**Fix (foundation, not a bigger cap):** each screen becomes ONE scroll view
of slivers (`CustomScrollView`): the card in a `SliverToBoxAdapter` (always
mounted — only `SliverList`/`SliverGrid` children are built lazily), then
the filters/warning, then the loans as `SliverList`/`SliverGrid` (still
lazy). The card scrolls away with the content, so no height can overflow;
the 40 % cap and the nested `SingleChildScrollView` existed only for the
`Column` and are removed (a scroll view inside a same-direction scroll view
is a Material anti-pattern). Reference: Flutter `CustomScrollView` /
`SliverToBoxAdapter` / `SliverFillRemaining` API docs (SDK).
